3D Viewer for WordPress

3D Viewer embeds interactive 3D models and 360° product views anywhere on your WordPress site — posts, pages, widgets, page builders and WooCommerce products — with no code.

What you can build

  • A standalone 3D model on any post or page, sized and styled to fit your layout.
  • A gallery of several models in one viewer, switchable by thumbnails or arrows.
  • Interactive hotspots that reveal text or link out when a visitor clicks a point on the model.
  • Augmented reality — visitors place the model in their own room from a phone.
  • WooCommerce product views, including per-variant models, a dedicated 3D tab, and 3D previews in shop listings.

Two viewers, one plugin

Every viewer you create runs on one of two rendering engines. You pick it with the Viewer control, and the choice decides which other options are available.

Viewer Best for Notes
Lite
default		 .glb, .gltf The full feature set: hotspots, AR, poster, skybox, environment lighting, exposure, tone mapping, textures, animation and variant selectors, initial view, capture button.
Advanced Almost every other format Broad format support with a smaller set of options: fullscreen, mouse control, zoom, zoom buttons, edge display, thumbnails and arrows. No hotspots, AR, poster or skybox.

The Advanced viewer reads .obj, .3ds, .stl, .ply, .gltf, .off, .3dm, .fbx, .dae, .wrl, .3mf, .amf, .ifc, .brep, .step, .iges, .fcstd and .bim. See Model Sources & File Types for which of those WordPress will let you upload.

Requirements

  • WordPress 6.5 or newer
  • PHP 7.4 or newer
  • A browser with WebGL — every current desktop and mobile browser qualifies
  • WooCommerce (only for the product features) and Elementor 2.0+ (only for the widgets)

Installation & Activation

Install the plugin, activate your licence, and run the one-time setup wizard.

Install the plugin

  1. Download the Pro zip
    It arrives with your purchase from bPlugins, or from your account area.
  2. Upload it
    In WordPress go to Plugins → Add New → Upload Plugin, choose the zip and select Install Now.
  3. Activate
    Select Activate Plugin. A 3D Viewer item appears in the admin sidebar.
Running the free plugin too?

The free and Pro editions share the same internal name and the same stored data, so only one should be active. Deactivate 3D Viewer (free) before activating 3D Viewer Pro. If both are active, Pro's features can silently stop rendering.

Activate your licence

Pro features stay locked until the licence is activated.

  1. Open the licence screen
    Go to 3D Viewer → Help & Demos, or use the account link the plugin adds under the 3D Viewer menu.
  2. Paste your licence key
    Use the key from your purchase email, then submit.
  3. Confirm
    Pro-only controls stop showing the orange Pro badge, and the upgrade banner disappears from the metabox.
If a licence lapses

When the licence expires the plugin falls back to free behaviour. Existing Pro settings stay in the database, but Pro-only output (skybox, AR, hotspots) stops rendering, and saving a viewer from the free metabox only writes back the fields the free edition owns. Renew before re-saving models you care about.

The setup wizard

Right after activation the plugin sends you to a four-step wizard at admin.php?page=bp3d-setup-wizard:

  1. Welcome — a summary of the two viewers.
  2. Choose How to Generate Shortcode — pick Gutenberg Block or Classic Editor. This writes the Enable Gutenberg setting described in Global Settings, which decides how new 3D Viewer posts open.
  3. Available Options — a tour of the Model and Options panels.
  4. Publish & You're All Set — embedding and quick troubleshooting.
The wizard runs once

Opening the page marks it complete, and later visits redirect to the 3D Viewer list. You can change the same setting any time at 3D Viewer → Settings → Shortcode Generator.

Quick Start

From a fresh install to a model on a live page, in about three minutes.

1. Create the viewer

  1. Go to 3D Viewer → Add New
    Give it a title — the title is only an internal label, so name it something you will recognise in the list.
  2. Add your model
    In the Model tabpanel, leave Viewer on Lite for a .glb or .gltf file, then upload the file or paste its URL. For any other format switch to Advanced first.
  3. Check it in the preview
    The Live Preview panel renders the model as you edit. Drag to orbit, scroll to zoom.
  4. Save
    Select Save (the Publish button is relabelled on this screen).

2. Copy the shortcode

Once saved, the shortcode appears directly under the title — select it to copy, or use the copy icon beside it.

[3d_viewer id="123"]

The same shortcode is listed in the ShortCode column of 3D Viewer → All 3D Viewers.

3. Put it on a page

Paste the shortcode into any post, page, widget or builder text area — a Shortcode block in Gutenberg, a Text widget, or a Shortcode/Text Editor widget in Elementor.

Prefer to skip the shortcode?

Insert the Model Viewer block (Gutenberg) or the Model Viewer widget (Elementor) straight into the page and configure it there. See Blocks & Page Builders.

4. Tune it

  • Size and alignment → Sizing, Styling & Custom CSS
  • Rotation, zoom, buttons and loading → Viewer Options & Controls
  • The angle the model first appears at → Initial View & Camera
  • Clickable labels on the model → Hotspots & Annotations

Choosing Your Editor

A saved viewer can be built in the classic metabox — a tabbed settings panel — or the Gutenberg block editor — block-based, with a live preview you can click. Both produce exactly the same [3d_viewer id="…"] shortcode; only the way you configure the viewer differs. One setting decides which one opens.

Set your editor in Settings

  1. Go to 3D Viewer → Settings
  2. Open the Shortcode Generator tab
  3. Toggle Enable Gutenberg
    Yes — Add New opens the Gutenberg block editor.
    No (the default) — Add New opens the classic metabox screen.
  4. Save
    The next viewer you create uses that editor.
Viewers remember their editor

Which editor a viewer uses is recorded when it is created. A viewer built in Gutenberg always reopens in Gutenberg, and one built in the classic screen always reopens there — flipping this setting only affects viewers you add from that point on.

To move an existing viewer across, create a new one in the other editor and copy the settings over; there is no in-place conversion. Its shortcode ID will change with it.

Where Elementor fits

This setting only controls the viewer editor. Elementor is a separate path: its Model Viewer widget configures a viewer in place on the page, without creating a saved viewer or a shortcode — and without hotspots, captured initial views or texture editing. When you need those on an Elementor page, build the viewer at 3D Viewer → Add New and drop its shortcode into a Shortcode widget.

Still unsure?

  • Pick Gutenberg if you want to click hotspots straight onto the model, adjust textures, or set the camera by eye.
  • Pick Classic if you prefer every option laid out on labelled tabs, or you are working on a site that does not use the block editor.
  • Either way, start with the Quick Start — the first viewer takes about three minutes.

Model Sources & File Types

Upload a model to the Media Library or point the viewer at a URL — and make sure WordPress accepts the file type first.

Uploading vs linking

  1. Open the Model tab
  2. Set Model Source Type
    Upload (default) opens the Media Library. Link Pro gives you a text field for an external URL.
  3. Fill in 3D Source
    Either pick the uploaded file or paste the full URL.
  1. Open the Model panel
  2. Use the Model URL field
    The same field does both jobs: the button opens the Media Library, and the text input accepts a pasted URL Pro.
  1. Open Content → Model Viewer
  2. Use Select Model
    Pick a file from the Media Library or paste a model URL into the same control.
External URLs need CORS

A model served from another domain (S3, a CDN, Google Drive) is fetched by the browser, so that host must send Access-Control-Allow-Origin. Without it the model silently fails to load even though the URL opens fine in a new tab.

Allowing 3D file types in the Media Library

WordPress blocks unfamiliar extensions by default. 3D Viewer can extend that list, but only for the types you tick.

  1. Go to 3D Viewer → Settings → General Settings
  2. Tick the types you need under Allowed Mime Types
    GLB, GLTF, OBJ, 3DS, STEP, STL, FBX, 3DML, DAE, WRL, 3MF, MTL, HDR and USDZ.
  3. Save, then upload
    The Media Library now accepts those extensions.
Existing installs

On upgrade the plugin seeds this list with all fourteen types so nothing breaks. On a fresh install nothing is ticked, and until you save the section the plugin falls back to allowing glb, gltf, obj, 3ds, step, stl, fbx, dae, wrl, 3mf, hdr and usdz.

Double extensions are rejected

Files like model.php.glb are refused on purpose, as is any file whose real content type looks like PHP. This is a security guard, not a bug.

Which format for which viewer

Format Viewer Notes
.glb (recommended) Lite Single file, textures embedded. The best-supported option.
.gltf Lite References external .bin and texture files — upload those too, keeping the relative paths intact.
.usdz Lite (AR only) Used only as the iOS AR source. See Augmented Reality.
.obj, .stl, .3ds, .fbx, .dae, .wrl, .3mf, .step, .ply, .off, .3dm, .amf, .ifc, .brep, .iges, .fcstd, .bim Advanced Rendered by the Advanced engine; Lite-only features are unavailable.

The extension decides the engine at render time

Selecting Lite and then giving it an .obj file does not work. Match the file to the viewer.

Draco-compressed models

If your .gltf was exported with Draco compression, set Use Decoder to Draco and supply the companion Bin File.

Not in the classic metabox

The decoder controls are exposed in the Gutenberg block and the Elementor widget. For a Draco model, build the viewer there — or use an uncompressed export.

Both controls sit in the Model panel, and the Bin File field only appears once Draco is selected.

Both controls sit in Content → Model Viewer, and Upload bin file only appears once Draco is selected.

Keeping models fast

  • Aim for a few MB, not tens of MB — the whole file downloads before the model appears.
  • Resize textures to 2048 px or less; textures usually dominate file size.
  • Prefer .glb over .gltf + loose files: one request instead of many.
  • Set Loading Type to Lazy for models below the fold — see Viewer Options.
  • Add a poster image so visitors see something immediately.

Visual Editor

A scratch canvas for placing hotspots on a model and capturing camera values you can paste back into any viewer.

What it is — and isn't

Open it at 3D Viewer → Visual Editor. It loads a single, unsaved Model Viewer block with the Pro controls unlocked, so you can load any model, click points on it, and copy the resulting coordinates.

Nothing here is saved

The Visual Editor does not write to a viewer, a product or a page. It is a measuring tool: you copy values out of it and paste them into the viewer you are actually building. Reloading the page discards everything.

Placing hotspots

  1. Load your model
    In the Model panel, set Model URL to the same file the real viewer uses. Coordinates are relative to the model, so it must be the same file.
  2. Frame the shot
    Orbit and zoom until you are looking at the point you want to annotate.
  3. Select Add Hotspot
    In the Hotspots/Annotations panel. The hint "Click on the model in the preview to add a hotspot" appears.
  4. Click the model
    A hotspot is created at that surface point and selected in the list.
  5. Copy the values
    Each of Hotspot Position, Hotspot Normal, Camera Orbit, Camera Target and FOV has a copy button beside it.
  6. Paste them into your viewer
    Into the matching hotspot fields — see Hotspots & Annotations.
Fewer fields on purpose

In the Visual Editor a hotspot shows only its Name and the five coordinate fields. Title, type, description and link settings belong to the viewer you paste into, so they are hidden here. The Style tab, the Additional panel and Use Multiple Model? are hidden for the same reason.

Capturing an initial view

  1. Load the model and frame the camera
  2. Select Copy Current/Initial View
    The button sits under the preview and copies a small JSON string.
  3. Paste it into the Initial View field
    Of the viewer, cycle-model row or product model you are configuring.
{"orbit":"37.6deg 74.2deg 2.4m","target":"0m 0.5m 0m","fov":"31.6deg"}

Illustrative shape only — copy the real value from the editor rather than typing one by hand.

When you don't need it

Building in the Gutenberg block? You can place hotspots and capture the initial view directly on the block's own preview — the values are stored in the block, so there is nothing to copy.

Everywhere else — the classic metabox, each cycle-model row, and the WooCommerce product metabox — the hotspot and Initial View fields only accept pasted values, and the Visual Editor is where you produce them. The classic Live Preview panel renders your settings but does not write coordinates back into the fields.

Initial View & Camera

Decide exactly which angle, distance and framing a visitor sees first. Pro

Why set one

By default the viewer frames the whole model from a generic angle. An initial view lets you open on the detail that sells the product — the front of a shoe, the dial of a watch — instead of whatever the exporter happened to leave as the default camera.

Capturing it

  1. Turn off Auto Rotate
    Otherwise the model moves while you aim.
  2. Frame the model on the block preview
    Orbit, pan and zoom until it looks right.
  3. Select Set Current as Initial View
    The button sits directly below the preview.
  4. Check it
    See Initial View jumps the camera back to the stored angle; Remove Initial View clears it.
  5. Update the page
  1. Open 3D Viewer → Visual Editor in a new tab
  2. Load the same model file
    Camera values are model-relative, so it must be the same file.
  3. Frame the model, then select Copy Current/Initial View
  4. Paste into Initial View
    Back in the Model tab of your viewer — or into the matching field inside a cycle-model row.
  5. Save
    The Live Preview panel now opens at that angle.
  1. Use Rotate for a simple starting angle
    Turn on Rotate, then set Rotate Along X (degree) and Rotate Along Y (degree) — 0–360 each, Y defaults to 75.
  2. For precise framing, build the viewer elsewhere
    Full initial-view capture is not an Elementor control.
No JSON initial view in Elementor

The widget exposes the two rotation angles but not the captured camera (orbit, target and field of view). For that, create the viewer at 3D Viewer → Add New, capture the initial view there, and place its [3d_viewer] shortcode in a Shortcode widget.

What gets stored

The value is a small JSON object holding the camera orbit, the target point and the field of view. Paste it whole — editing it by hand is rarely worth the trouble.

{"orbit":"37.6deg 74.2deg 2.4m","target":"0m 0.5m 0m","fov":"31.6deg"}
Change the model, re-capture the view

Coordinates are tied to the model's own geometry and scale. Swapping in a re-exported file usually invalidates the stored view. The block clears the initial view for you whenever you pick a new model URL.

Per-model views

In a multi-model viewer each model carries its own Initial View, so every item in the gallery can open on its own best angle. See Multiple Models.

Related camera controls

  • Zoom LevelInitial Zoom — a quick way to start closer or further out without capturing a full view.
  • Show Reset View Button — gives visitors a way back to your initial view after they have spun the model around.
  • Auto Rotate — starts from the initial view and orbits from there.

Poster image

A poster is the still image shown in place of the model until it has finished downloading. On a large model it is the difference between an empty box and a product photo.

Set 3D Poster Image on the Model tab (single-model viewers), or 3D Poster inside each cycle-model row.

Set Model Poster in the Model panel — or per item in a multi-model viewer.

Set Select Poster in Content → Model Viewer — or per item in the Models repeater.

Posters double as thumbnails

In a multi-model viewer the poster is what appears in the thumbnail strip. Models without one show a number instead.

Environment image

An environment image lights the model and produces its reflections. It is not shown as a background unless you also make it the skybox.

In the Model panel:

  • Environment Image — choose Neutral (default) or Legacy, or upload your own with Upload Environment Image.
  • Use Environment as Skybox — also paints it behind the model.
  • Tone Mapping — Neutral (default), ACES or agX. ACES gives a filmic, slightly contrastier look.

Upload an image or HDR file into Environment Image on the Model tab (single-model viewers) or inside a cycle-model row.

Presets and tone mapping are Gutenberg-only

The Neutral/Legacy environment presets, Use Environment as Skybox and Tone Mapping are exposed in the Gutenberg block. In the metabox you supply your own environment file instead.

Use Environment Image in Content → Model Viewer (single-model viewers only).

Presets and tone mapping are Gutenberg-only

The Neutral/Legacy presets, Use Environment as Skybox and Tone Mapping are exposed in the Gutenberg block. The widget takes an environment file only, and only for a single model.

HDR skybox

A skybox replaces the background with a 360° image and lights the model from it — the quickest way to make a product look photographed rather than rendered.

  1. Get an HDR or panoramic image
    An .hdr file gives the best lighting. Enable HDR uploads first — see Model Sources & File Types.
  2. Set it on the viewer
    Upload it into HDR Skybox Image on the Model tab, or Skybox Image in a cycle-model row.Use HDR skybox image in the Model panel — and Skybox Height, which appears once an image is set, to shift the horizon.Use HDR Skybox Image in Content → Model Viewer, or per item in the Models repeater.
  3. Adjust Exposure
    HDR skyboxes often need the exposure pulled down.
Skyboxes are heavy

An HDR panorama can easily exceed the model itself. Keep it under a couple of megabytes, or the viewer stays blank far longer than it needs to.

Background colour is ignored when a skybox or background image is set

The skybox wins over the background colour. Clear it if you want a flat colour back.

Exposure and shadow

Exposure brightens or darkens the whole scene — raise it for a model that renders too dark, lower it under a bright skybox.

shadow Intensity (default 1) controls how dark the ground shadow is. Both fields are on the Settings tab.

Enable Shadow draws a soft contact shadow under the model, which anchors it to the page instead of leaving it floating.

In a multi-model viewer, exposure is set per model.

Textures (Experimental)

Recolour a material or swap its texture map without re-exporting the model. Pro

Experimental

The panel is labelled experimental in the plugin itself. It works best on simple, well-named materials in .glb files; complex models with many materials may respond unpredictably. Keep a copy of the original file.

Opening the panel

The Texture (Experimental) panel appears in the block's Settings tab only when all of the following are true:

  • the Lite viewer is selected;
  • the viewer holds a single model (not a multi-model gallery);
  • a Model URL is already set;
  • the Pro licence is active.

If the model's materials have not been read yet, select Load Texture. If the model has no materials the panel simply says No material found.

Texture editing is Gutenberg-only

The texture panel exists in the Gutenberg block and the Visual Editor. It is not part of the classic metabox — build the viewer with the block, or edit the material in your 3D software before export.It is not an Elementor control — build the viewer with the block, or edit the material before export.

Editing a material

  1. Pick the material
    Selected Material lists every material in the model.
  2. Open a channel
    Base Color for colour and its texture map; Metallic Roughness for how metallic and how glossy the surface is.
  3. Change the factor
    Under Base Color, the Factor colour picker tints the material. The undo arrow beside it restores the model's own value.
  4. Or change the texture
    Available Textures shows the maps already inside the model — select one to apply it, or select the empty square to remove the map. Upload a Texture applies an image from the Media Library.
  5. Tune metallic/roughness
    Two sliders, 0–1 each. Low roughness is mirror-like; high roughness is matte.
  6. Update the page
    Changes are stored with the block and applied on the front end.

Tips

  • Name materials meaningfully before export ("Body", "Trim") — the dropdown shows those names.
  • Uploaded textures should match the UV layout of the map they replace, or they will smear.
  • Changes apply to that block only; they do not alter the source file.
  • For a permanent change across many pages, edit the model in your 3D software instead.

Variable Products

Show a different model as the shopper changes colour, size or any other attribute.

How it works

When a product has variations, the plugin adds a Select (attribute) dropdown to every row in Product 3D Models. Assigning a model to a variant value means it is shown whenever the shopper selects that value; All (the default) means the model is used for every variant.

Setting it up

  1. Create the variations first
    The dropdowns are built from the product's existing attributes, so save your variations before opening the 3D Viewer metabox.
  2. Add one model row per variant
    Under Product 3D Models.
  3. Map each row
    Set the Select … dropdown to the matching attribute value.
  4. Turn off the carousel
    Set Show Thumbnail List and Show Arrows to No — the field help says "Carousel should be disabled", because manual switching conflicts with automatic variant switching.
  5. Update the product and test
    Change the variation on the front end and confirm the model follows.
Only attributes with more than one value get a dropdown

If an attribute has a single value across all variations there is nothing to choose between, so no selector is added for it.

Re-save after changing variations

Adding, renaming or removing a variation changes the attribute values the dropdowns are built from. Re-open the product, check each mapping, and update — this is what the admin notice on product screens is reminding you about.

Tips

  • Keep one fallback row set to All so shoppers always see something before choosing a variation.
  • Give every model the same camera framing and scale, or the viewer will appear to jump as variants change.
  • For products with many attributes, map on the one that actually changes the appearance — usually colour or material.

Shortcode Reference

Two shortcodes: one for saved viewers, one for WooCommerce products.

[3d_viewer]

Renders a viewer created at 3D Viewer → Add New.

[3d_viewer id="123"]
Attribute Required Notes
id Yes The ID of a 3D Viewer post (or a WooCommerce product). Without it, nothing renders.
Only id has an effect

The shortcode also accepts src, alt, width, height, auto_rotate, camera_controls, zooming_3d, loading and poster, but every one of them is ignored — the viewer is rendered entirely from the settings saved on the viewer itself. Change the size or behaviour by editing the viewer, not the shortcode.

Find the ID under the viewer's title on its edit screen, in the ShortCode column of the list table, or in the URL (post.php?post=123&action=edit).

Where to paste it

  • Gutenberg — a Shortcode block (or type the shortcode into a paragraph).
  • Classic editor — anywhere in the content.
  • Widgets — a Text or Shortcode widget.
  • Elementor — a Shortcode widget.
  • Theme templates — see the PHP form below.
<?php echo do_shortcode('[3d_viewer id="123"]'); ?>

[3d_viewer_product]

Renders the 3D models configured on a WooCommerce product, using that product's own metabox settings.

[3d_viewer_product id="99"]
Attribute Required Notes
id No Defaults to the current post. Must belong to a product, or nothing renders.
It renders the current product, not the one in id

The id attribute is only used to confirm the target is a product — the model that actually renders comes from the product WooCommerce is currently displaying. In practice that means the shortcode belongs in a product description or a product template. On a normal page or post outside the product loop it outputs nothing, even with a valid product ID.

To show a specific product's model on an arbitrary page, build a viewer at 3D Viewer → Add New and use [3d_viewer] instead.

The template form, as printed in the product metabox:

<?php echo do_shortcode('[3d_viewer_product id="' . get_the_ID() . '"]'); ?>

The width and late_initialize attributes are accepted but have no effect; size the viewer with the product's Height field and your theme's layout.

Uninstall deletion is permanent

With the switch on, removing the plugin from the Plugins screen deletes every viewer and preset you have built. Deactivating alone never deletes anything, and neither does uninstalling while the free plugin is still active. Leave it off unless you are deliberately cleaning up.

Preset

Defaults for newly created viewers: width (100%), height (320px), background colour (transparent), autoplay, shadow intensity (1), preload, moving controls, zoom, progress bar, loading type, auto-rotate, rotate speed (30), rotation delay (3000 ms) and fullscreen.

Two quirks worth knowing

Preload has no matching control on the viewer and currently does nothing — set your loading behaviour with Loading Type instead.

Auto Rotate Speed and Auto Rotation Delay on this tab are tied to the Auto Rotate switch on the Woocommerce Settings tab (they share a field name). If those two fields are missing here, turn Auto Rotate on over there.

Defaults are not retroactive

These values seed new viewers. Viewers that already exist keep whatever they were saved with.

Troubleshooting

The problems that come up most often, and what actually fixes them.

The model does not appear

  1. Open the model URL directly
    Paste it into a browser tab. If it does not download, the file is missing or blocked — fix that first.
  2. Check the format matches the viewer
    .glb/.gltf need Lite; everything else needs Advanced. This is the single most common cause.
  3. Check the browser console
    A CORS error means the model is on another domain that is not sending Access-Control-Allow-Origin. Move the file to your own site or configure the host.
  4. Confirm the viewer has height
    A viewer with no height renders as an invisible strip. See Sizing & Styling.
  5. Check the file uploaded intact
    A .gltf needs its .bin and texture files alongside it, at the same relative paths.

It works in the editor but not on the front end

  • Caching plugin — purge the cache after saving, then reload.
  • JavaScript optimisation — combining, deferring or delaying scripts can break the viewer. Exclude frontend.js, model-viewer.latest.min.js and o3dv.min.js from concatenation and "delay until interaction" features.
  • Mixed content — a model loaded over http:// on an https:// page is blocked by the browser.
  • Console errors from another plugin — a JavaScript error anywhere on the page can stop the viewer from starting. Check the console before assuming the plugin is at fault.
A fallback viewer means something crashed

If you see a plain, unstyled model with none of your settings, the viewer hit an error and fell back to a basic render so the model still shows. The browser console will name the cause.

The model is black, white or badly lit

  • Raise Exposure — many exports are dark by default.
  • Add an Environment Image or HDR skybox: a model with no lighting information renders flat. See Lighting.
  • Check the export includes materials — a mesh with no material shows as plain white.
  • If the background swallows the model, set a contrasting Background Color.

Loading is slow

  • Reduce the file size: fewer polygons, textures at 2048 px or less, .glb rather than .gltf + loose files.
  • Set Loading Type to Lazy for viewers below the fold.
  • Add a poster image so the space is not empty while downloading.
  • Turn on the progress bar or loading percentage so visitors know something is happening.
  • Check the skybox — HDR panoramas are often larger than the model itself.

WooCommerce: the viewer is in the wrong place

  1. Check 3D Viewer Position
    On the product, not in global settings.
  2. Try Dedicated Tab
    It sidesteps the theme's gallery markup entirely and is the most reliable option.
  3. Mark the theme incompatible
    Settings → Woocommerce Settings → 3D Viewer is not Compatible with this Theme switches to JavaScript placement.
  4. Adjust the gallery selectors
    Settings → Woocommerce Selectors — see Viewer Position & Themes.

WooCommerce: nothing shows on the product at all

  • Is Woocommerce enabled in 3D Viewer → Settings → Woocommerce Settings? Off hides the metabox and stops all rendering.
  • Does the product actually have a model row under Product 3D Models?
  • Is 3D Viewer Position still None? Then nothing is placed automatically — that is by design.
  • On shop and category pages, remember that Display 3D models… needs Display 3D icon… switched on as well.

Hotspots are missing or in the wrong place

  • Hotspots need the Lite viewer — the Advanced viewer never renders them.
  • Coordinates were captured against a different model file. Re-capture in the Visual Editor with the exact file the viewer uses.
  • The style is Simple Tag, which deliberately shows no description or link button. Switch to a card style.
  • The Elementor widget does not render hotspots at all — embed the shortcode instead.

The upload is rejected

  • Tick the extension at Settings → General Settings → Allowed Mime Types.
  • Files with a double extension (model.php.glb) are refused on purpose — rename the file.
  • "Exceeds the maximum upload size" is a server limit, not a plugin one. Raise upload_max_filesize and post_max_size, or upload by FTP and paste the URL.

Pro features look locked

  • Confirm the licence is active — see Installation & Activation.
  • Make sure the free 3D Viewer plugin is deactivated; running both causes exactly this.
  • If the licence recently expired, Pro output stops rendering even though the settings are still stored. Renew, then re-check the affected viewers.

Still stuck

Contact bPlugins support with: the page URL, the model URL, which viewer engine you selected, your theme name, and any console errors. That combination usually resolves it in one reply.

Frequently Asked Questions

Models and formats

Which format should I use?

.glb. It packs geometry and textures into one file, loads fastest, and unlocks every Lite-viewer feature — hotspots, AR, skybox, textures, initial view.

Can I use models from Sketchfab or another marketplace?

Yes, provided the licence permits it and you can download a .glb, .gltf or one of the Advanced-viewer formats. Upload the file, or host it and paste the URL.

Can models be served from S3, a CDN or Google Drive?

Yes — that is what the Link source type is for. The host must send permissive CORS headers, and the URL must point at the file itself rather than a preview page.

Is there a file size limit?

Only your server's upload limit. Practically, keep models to a few megabytes: everything downloads before the model appears.

Features

Can I show several models in one viewer?

Yes — see Multiple Models. Visitors switch with thumbnails or arrows.

Does it work on phones and tablets?

Yes. Touch orbits and pinch zooms, and AR is a mobile feature by nature.

Can visitors download my model?

Not through the plugin, but the file is fetched by the browser, so a determined visitor can retrieve it from the network tab. Do not publish models you cannot afford to have copied.

Can I animate the model?

If the file contains animation clips: turn on Autoplay, and optionally the Animation Selector so visitors can choose a clip. Lite viewer only.

Does the viewer affect SEO or Core Web Vitals?

The model is loaded by JavaScript, so it is not indexed as content. Use Lazy loading and a poster image to keep layout shift and load time in check.

WooCommerce

Can each variation have its own model?

Yes — see Variable Products. Disable the thumbnail carousel when you do.

Can I show 3D on shop and category pages?

Yes, via the two listing switches on the product. See Shop Listings & Popups.

My theme's gallery breaks when I enable the viewer.

Use the Dedicated Tab position, or mark the theme incompatible and adjust the gallery selectors. See Viewer Position & Themes.

Licence and data

Do I lose my work if the licence expires?

No. Settings stay in the database. Pro-only output stops rendering until you renew, and saving a viewer while unlicensed only rewrites the fields the free edition owns — so renew before re-saving important viewers.

Can I run the free and Pro plugins together?

No. They share the same identity and the same stored data. Deactivate the free plugin before activating Pro.

What happens when I delete the plugin?

Nothing is removed unless Delete data on uninstall is switched on. With it on, uninstalling deletes all viewers, presets and plugin settings permanently.

Can I move viewers to another site?

Yes — export the 3D Viewer posts with WordPress' exporter and import them on the other site, then re-upload the model files (or keep them on a shared URL). Post IDs change, so update your shortcodes afterwards.

Editors

Which editor should I build in?

The one you already use. The classic metabox and the Gutenberg block both produce a reusable viewer plus a shortcode; the Elementor widget is inline-only and lacks hotspots, initial view and textures.

How do I switch an existing viewer to the block editor?

You cannot convert one in place. Enable Enable Gutenberg and create a new viewer, then move your settings across and swap the shortcode.

Why are there two 3D blocks in the inserter?

Model Viewer is the full-featured block; 3D Viewer is a minimal one with just source, size and zoom. See Blocks & Page Builders.
